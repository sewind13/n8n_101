# l3_reimbursement — ระบบเบิกเงินผ่าน LINE

สองไฟล์ทำงานคู่กัน

| ไฟล์ | หน้าที่ |
|---|---|
| `l3_reimbursement.json` | รับคำขอเบิก + รับสลิป + ให้พนักงานกดยืนยันว่าสลิปเป็นของใบไหน |
| `l3b_reimbursement_expiry.json` | รันวันละครั้ง เตือนวันที่ 5 และยกเลิกใบที่ไม่มีหลักฐานเกิน 7 วัน |

## ต้องตั้งค่าก่อนเปิดใช้

1. **เพิ่มหัวคอลัมน์ในชีท `reimbursement_tracking` แถวแรก** ให้ครบ 8 คอลัมน์ ตามลำดับนี้

   `Id | Date | Name | UserId | Description | Amount | Status | SlipUrl`

   ของเดิมมี 6 คอลัมน์ — ที่เพิ่มคือ **`UserId`** (ใช้กรองว่าใบไหนเป็นของใคร ใช้ `Name`
   ไม่ได้เพราะ display name ซ้ำกันได้และเปลี่ยนได้) และ **`SlipUrl`**

2. **ผูก credential ของ Google Drive** ที่โหนด `Upload Slip to Drive` — โหนดนี้ยังไม่มี
   credential ติดมา (flow เดิมไม่เคยใช้ Drive) ตอนนี้อัปลง My Drive root เปลี่ยนเป็น
   โฟลเดอร์เฉพาะได้ที่ช่อง Folder

3. **แชร์โฟลเดอร์ Drive ให้ฝ่ายบัญชี** ไม่งั้นลิงก์ใน `SlipUrl` จะเปิดไม่ได้

4. เปิด `l3b_reimbursement_expiry` ให้ active ด้วย ไม่งั้นใบค้างจะไม่มีวันหมดอายุ

## สถานะในคอลัมน์ Status

| ค่า | ความหมาย |
|---|---|
| `รอหลักฐาน` | สร้างใบแล้ว ยังไม่มีสลิป — ใบพวกนี้คือตัวเลือกที่โผล่ใน carousel |
| `รอตรวจ` | แนบสลิปแล้ว รอฝ่ายบัญชีตรวจ |
| `ยกเลิก (ไม่มีหลักฐาน)` | เกิน 7 วันแล้วไม่มีสลิป ระบบยกเลิกให้ |

ฝ่ายบัญชีแก้ต่อเองในชีทได้ (เช่นเป็น `อนุมัติ`/`ไม่อนุมัติ`) ระบบไม่ยุ่งกับค่าที่ไม่รู้จัก

## ทำไมถึงออกแบบแบบนี้

- **ไม่เดาว่าสลิปเป็นของใบไหนเด็ดขาด** — แม้เหลือใบค้างใบเดียวก็ยังให้กดยืนยัน เพราะเคส
  ที่อันตรายที่สุดคือใบค้างใบเดียวนั้นเป็นใบเก่าที่ลืม ส่วนสลิปที่เพิ่งส่งเป็นของรายการใหม่
  ที่ยังไม่ได้แจ้ง ถ้าจับคู่ให้อัตโนมัติจะผิดแบบเงียบๆ
- **อัปรูปขึ้น Drive ทันทีที่รับ ไม่รอตอนกดปุ่ม** — เนื้อไฟล์ใน LINE
  (`/v2/bot/message/{id}/content`) หมดอายุ ถ้าเก็บแค่ `messageId` ไว้รอ พอกดปุ่มวันรุ่งขึ้น
  รูปจะหายทั้งที่ชีทบอกว่าแนบแล้ว
- **`Re-read Claim Row` + `Still Open & Owner?` อ่านชีทใหม่ทุกครั้งตอนกดปุ่ม** — ปุ่มเก่า
  ค้างอยู่ในแชทตลอดไป เลื่อนขึ้นไปกดซ้ำได้เสมอ ถ้าใบปิดไปแล้วจะตอบปฏิเสธแทนการเขียนทับ
  และเช็คด้วยว่า `UserId` ตรงกับคนที่กด
- **เอา `Simple Memory` ออกจาก AI Agent** — memory ทำให้ข้อความกำกวมอย่าง "อันนั้นแหละ"
  ถูกเติมด้วย item/amount ของใบก่อนหน้าแล้วสร้างแถวซ้ำ ตอนนี้ตัดสินจากข้อความปัจจุบันอย่างเดียว
  และถ้ากำกวมจะตอบปฏิเสธแทนการเดา
- **`Id` ใช้ `$execution.id`** แทน `Math.random()*10000` ของเดิม ซึ่งวันละ ~100 ใบมีโอกาส
  ชนกันเกิน 40% (birthday problem) และ `Id` คือกุญแจเดียวที่ใช้อ้างอิงทั้งระบบ
- **`Route Event` แยก text / image / postback ตั้งแต่ต้นทาง** — flow เดิมอ่าน
  `message.text` เสมอ ส่งรูปมาจะกลายเป็น `undefined` แล้วตอบว่าไม่เกี่ยวกับการเบิก
  เส้นทาง postback ไม่ผ่าน AI Agent เลย เพราะเป็นข้อมูลที่ชัดเจนอยู่แล้ว

## ที่ยังไม่ได้ทำ

- ปุ่ม **"เปิดใบใหม่"** ตอบกลับเป็นลิงก์สลิปแล้วให้พิมพ์รายการเข้ามาใหม่ + ส่งสลิปซ้ำ
  ยังไม่ได้ทำ state ค้างไว้ให้แนบอัตโนมัติ (สลิปอยู่บน Drive แล้ว ไม่หาย)
- ยังไม่มีขั้นตอนอนุมัติของฝ่ายบัญชีใน LINE — ตอนนี้ตรวจในชีท
